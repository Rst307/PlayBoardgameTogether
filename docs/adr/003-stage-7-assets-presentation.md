# ADR-003：不可变资源与按同步世代消费的表现事件

日期：2026-09-25

状态：Accepted（第七阶段实施）

资源由 API assets 模块拥有，持久元数据在 PostgreSQL，字节在独立本地目录。游戏通过单独 assets 入口声明槽位和已投影事件的 cue；不修改被旧规则摘要覆盖的 SDK index、规则/shared index 或 server 文件。协议暴露精确版本、摘要与文件 ID，不传物理路径。

现有 Color Match default@1.0.0 是真实空清单，历史对局继续其 CSS 语义表现，不能把新图片伪装成旧摘要。新房默认引用新图片版本，旧局保留原资源摘要。对局规则恢复与资源加载分离；资源故障不会阻断 View 和合法动作。

数据库内资源操作使用统一事务 advisory lock；房间先锁 room 再取得资源锁。资源发布/归档/删除不反向取得 room 行锁。复制、引用、发布、tombstone 与 GC 在相同资源锁下检查，避免引用检查与开局竞态。文件处理在事务外，配额和 processing 状态先持久化；最终文件写入后短事务激活。孤儿延迟清理，绝不宣称数据库与文件系统共同原子提交。

音效只消费已同步连接中的 WS live 完整事件批次；HTTP 确认永不发声。每个 revision 的全部 cue 先消费后异步加载，随后关闭该 revision；拒绝旧 revision，用有界水位代替无限集合。服务端只有快照 revision 精确等于事件 revision 时发送整个投影批次，否则返回静默快照。initial/resync、断线、后台、owner 切换重建基线，不补历史。相同 revision 控制器状态更新无事件，不推进声音水位。

同账户/对局 Web Lock 持有者可播放；获得所有权后先拉权威快照。无 Web Locks 时保守停用自动游戏音效，用户仍可主动测试声音。音频延迟上限一秒，generation 变化使所有旧加载失效。预览仅用固定数据、点击试听，与对局事件隔离。

替代方案：运行时资源继承容易令历史依赖漂移，因此发布完整展开清单；每游戏播放器会绕过静音和去重，因此统一服务；新独立服务/消息队列无具体需求，继续模块化单体。
