# ADR-006：在线更新使用有限请求排空与持久对局恢复

日期：2026-10-04

状态：Accepted

## 背景

旧更新器要求连续 60 秒请求静默、零 WebSocket 和零 active matches。社交每 5 秒轮询、常驻房间页面和未结束的旧对局都能使已构建更新永久等待。单 API 没有零停机切换能力。

## 决定

候选构建成功后立即关闭公共 HTTP/WS 新请求入口，API 通过已有本地 IPC 设置闸门。现有 WS 发送 1012 并关闭，晚完成的已接收握手同样关闭，一秒后终止未响应连接。等待已接收 HTTP 请求最多 30 秒；超时恢复旧服务并报告 failed，保留候选以供重试。监督 IPC 超时 35 秒，取消世代后的结果不得用于下一次切换。

不以数据库 active matches 阻塞更新，不自动结束对局或改变成员、座位、控制权。复用 ADR-002 的 State/RNG/revision/命令回执恢复；先完成已接收请求，再沿用优雅停机、AI 任务关闭、数据库准备、候选就绪和失败恢复。保持精确规则版本与摘要检查、迁移默认待维护、session/Origin/CSRF、请求去重和不刷新玩家页面。

## 后果与边界

玩家会短暂断线，重连重新认证并获取权威快照，未知动作按原 requestId 恢复，不重复动作或历史事件。30 秒仅是请求排空期限，构建、迁移和启动有各自原有期限。部署不兼容规则、协议或迁移仍需维护，不能承诺零中断或数据库回退。首次启用必须在服务器选择新 API 版本并重启新版监督脚本，运行中的父脚本和 current.json 记录的旧 API 不会自动热替换。
