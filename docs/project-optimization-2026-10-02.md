# 项目优化审查与界面原则（2026-10-02）

本轮从当前代码核对结构与使用体验，落地平台入口、页面恢复、登录交互和依赖检查。保持 TypeScript/pnpm workspace、模块化单体、原生 CSS 和游戏扩展装配。本文区分已实现调整与后续建议；不是下一阶段全部功能的完成声明。

## 当前结构与本轮调整

```text
apps/web/src/app/
  App.tsx                 站点外壳、主导航、文档标题
  routes.tsx              页面匹配、页面元数据、按需加载
  RootPage.tsx            首页会话状态与大厅/访客页面
  developer-guides.ts     开发文档目录、标题与摘要
  PageBoundary.tsx        页面绘制/加载失败的恢复入口
  navigation.ts           站内链接、history、焦点与页面过渡

scripts/
  check-boundaries.ts      自动发现全部游戏并检查源目录
  dependency-boundaries.ts TypeScript AST 导入读取与层次约束

playwright.ui.config.ts   无数据库的生产外壳与公开文档回归
```

此前 App 同时拥有首页身份加载、路由、页面标题与外壳，并直接加载大部分页面。现在 App 负责外壳，routes 统一页面匹配与元数据；管理、资料、房间、对局和公开文档按页加载。保留房间/对局 ID 的挂载隔离以及旧页交互禁用。没有新增路由框架，也没有拆分 API 运行单元。

页面错误边界保留主导航；加载文件失败时用户可重新加载整页或打开其他页面。整页重新加载重新获取客户端模块和权威状态，不在本地重建对局。游戏内部既有错误边界继续负责扩展绘制。

真实 Color Match 回归进一步复现：历史对局加载后退出登录，WS 握手可能在服务端建立连接前拒绝，客户端未收到 4001；旧实现只在打开的 WS 上周期同步，无法及时清除已显示 View。现在一般断线也经认证 HTTP 复核，未认证时清除旧视图并停止重连。重连仍有页面世代/socket 检查，心跳、请求去重与游戏规则不变。

选中的真实流程测试将截图写入 Playwright 的独立输出目录，避免覆盖文档截图。Color Match 测试只在页面已加载后暂停时钟验证心跳，随后恢复时钟再验证刷新与导航，防止冻结 React Suspense 的加载计时器；原会话失效、心跳重连与单连接断言继续保留。

开发文档原先独立写入并在卸载时重置 document.title，生产回归暴露它与新外壳的竞争。文档目录供页面与路由共同使用，标题统一由外壳更新，保留各篇指南的具体名称。

## 界面六项原则

| 原则 | 实施与维护要求 |
| --- | --- |
| 层次清楚 | 页面标题解释当前位置；主操作先于帮助和技术信息。游戏桌优先，管理入口收在更多导航。 |
| 一致性 | 共用现有灰阶表面、间距、44px 控件、焦点和反馈；游戏语义颜色由扩展拥有，不为统一配色抹去牌/棋盘含义。 |
| 状态可见 | 区分加载、保存、等待、离线与失败。登录分别解释凭据错误、频控与连接失败，不显示原始服务错误或秘密信息。 |
| 防错与恢复 | 请求中锁定登录表单并拒绝重复提交；保留失败后的输入。未知动作结果仍走原回执恢复，页面加载失败保留导航。 |
| 用户控制 | 密码默认隐藏，可显式显示/隐藏；登录和 404 有返回入口。浏览器返回、链接修饰键、下载、锚点和更多菜单的选择继续保持。 |
| 可访问与适配 | 使用原生表单、标签、aria-busy/alert、跳转主内容和换页焦点；短桌面侧栏可滚动，手机自然纵向布局，遵循减少动态效果偏好。 |

这些是日常实现约束，不宣称取得无障碍认证。Chromium 桌面和 Pixel 5 模拟之外的实机、软键盘与 WebKit 仍需独立验收。

## 自动化边界

`pnpm lint` 使用 TypeScript AST 识别静态导入、再导出、类型导入、带注释的多行动态导入与 require；注释和普通字符串不当成依赖。覆盖 Web、UI、client-sdk、protocol、game-sdk 和每个游戏的 client/server/shared。

浏览器可达源目录禁止 Node 内置模块（包含子路径）、数据库/后端包、游戏 server 和 API 相对路径；protocol/game-sdk 保持平台与具体游戏独立；shared 规则不依赖 React/客户端传输，服务端扩展不依赖 React/数据库/平台应用。保留服务端现有资源文件读取。

它检查已列目录中的字面量依赖及归一化相对路径，不是完整打包器依赖图：计算型导入、自定义路径别名、第三方包内部依赖和 API 装配生命周期仍需类型检查、构建及运行验证。生产 bundle/runtime 检查继续执行，不能用 lint 替代它们。
