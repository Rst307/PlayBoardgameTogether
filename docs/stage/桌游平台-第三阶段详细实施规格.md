# 桌游平台-第三阶段详细实施规格

版本：1.0\
阶段：第三阶段------第一个完整真人游戏 Color Match

## 1. 阶段目标

本阶段目标：

> 在已经完成账户、房间、座位、开局系统的基础上，实现第一个完整规则驱动桌游，使真人玩家可以通过浏览器完成一整局游戏。

本阶段验证：

-   游戏扩展 SDK 是否满足真实桌游需求。
-   服务端权威状态是否可靠。
-   玩家私密信息是否隔离。
-   真人操作是否通过统一动作系统执行。
-   后续 AI 是否可以直接接入。

------------------------------------------------------------------------

# 3. Color Match 游戏规则

## 玩家数量

支持：

-   最少 2 人
-   最多 4 人

## 卡牌

牌组：

-   4 种颜色：
    -   红
    -   蓝
    -   黄
    -   绿

每种颜色：

-   数字 1-5
-   每个数字两张

总计：

40 张牌。

------------------------------------------------------------------------

# 4. 开局流程

服务器执行：

1.  创建牌堆。
2.  使用受控随机源洗牌。
3.  每名玩家获得 5 张手牌。
4.  翻开一张公共牌。
5.  设置第一行动玩家。
6.  创建游戏状态。

客户端只能收到：

-   自己手牌。
-   公共牌。
-   玩家列表。
-   当前行动玩家。

不能收到：

-   完整牌堆。
-   其他玩家手牌。

------------------------------------------------------------------------

  hands,
  discardPile,
  currentPlayerId,

规则要求：

-   不直接发送客户端。
-   所有修改通过 action 完成。

# 6. 玩家视图

View 根据玩家身份生成。

玩家 A：

可以看到：

-   自己手牌。
-   公共牌。
-   自己行动权限。
-   其他玩家手牌数量。

不能看到：

-   玩家 B 手牌。
-   剩余牌顺序。
-   服务器随机状态。

------------------------------------------------------------------------

# 7. 动作系统

所有操作统一格式：

``` json
{
 requestId,
 matchId,
 expectedRevision,
 action
}
```

动作：

## 出牌

``` json
{
 type:"play_card",
 cardId
}
```

## 摸牌

``` json
{
 type:"draw_card"
}
```

## 选择目标

``` json
{
 type:"choose_target",
 targetSeatId
}
```

------------------------------------------------------------------------

# 8. 合法性检查

服务端必须检查：

-   是否当前玩家。
-   卡牌是否属于该玩家。
-   卡牌是否存在。
-   是否符合规则。
-   目标玩家是否合法。

客户端提示只能用于体验。

不能相信：

-   客户端发送的 cardId。
-   客户端发送的当前玩家。
-   客户端发送的胜负结果。

------------------------------------------------------------------------

# 9. 回合系统

流程：

    玩家行动
     ↓
    提交Action
     ↓
    服务端验证
     ↓
    执行规则
     ↓
    生成事件
     ↓
    更新revision
     ↓
    广播玩家视图
     ↓
    进入下一玩家

失败：

-   状态不变化。
-   revision 不增加。
-   返回错误原因。

------------------------------------------------------------------------

# 10. 特殊效果

数字5：

打出数字5后：

-   当前玩家选择另一玩家。
-   对方摸一张牌。

限制：

-   不允许递归触发。
-   效果完成后进入下一回合。

------------------------------------------------------------------------

# 11. 游戏结束

胜利条件：

玩家打出最后一张牌。

服务器：

保存：

-   winner。
-   最终状态。
-   最后一条事件。

结束后：

任何动作拒绝。

------------------------------------------------------------------------

# 12. 游戏事件系统

事件用于：

-   前端展示。
-   后续音效。
-   回放。

事件示例：

``` json
{
type:"card.played",
playerId,
publicData
}
```

禁止：

公开事件包含：

-   隐藏手牌。
-   牌堆信息。
-   私密选择。
