# 桌游平台：第七阶段详细实施规格

版本：1.0  
日期：2026-09-25  
阶段：十阶段计划的阶段 7——图片与音效自定义  
交付对象：继续开发现有项目的 Codex

## 1. 前提、目标与文档关系

用户已确认第六阶段完成。本规格衔接第六阶段的资源交接要求，以及此前的版本锁定、玩家视图、事件去重与恢复约定。编写时已读取第六阶段交接内容，未检查实际代码，不代替前六阶段验收。

目标：管理员能上传图片、短音效和映射文件，校验并发布不可变资源版本；房主在开局前选择兼容资源包；同一个 Color Match 可以换整套卡面、牌背、桌面与声音，而无需修改规则、动作协议或 AI 提示词。客户端能真实显示与播放，并在断线、重连、重复事件和资源失败时正确降级。

沿用现有技术栈、认证、PostgreSQL、游戏 SDK、事件协议、前端组件与测试框架。本文命名和数值为实施默认值，等价实现可复用；必要调整写入 docs/decisions.md。涉及具体库与浏览器 API 时，开发者核对所用版本的官方文档，不猜测接口。

## 4. 五层数据边界

| 层 | 保存什么 | 不应承担什么 |
| --- | --- | --- |
| 游戏规则/内容 | 卡牌语义、合法动作、结算、逻辑资源 key | 文件路径、音量和播放状态 |
| 资源契约 | 所需槽位、类型、比例提示、允许声音 cue | 玩家当前手牌归属 |
| 资源包 manifest | key → fileId；cue → soundKey 的声明式映射 | 可执行代码、权限判定 |
| 文件存储 | 经过校验的图片/音频字节、hash、元数据 | 对局 State |
| 玩家 View/事件 | 当前玩家可见对象与表现提示 | 对手私密牌面 ID、内部事件全量 |

逻辑资源例子：card.red.1、card.back.default、board.table、sound.card.play。两张同面红 1 可以共用图像，不能用图片 key 当真实牌实例 ID。规则仍用原 card instance ID 维护牌堆和手牌。

静态全套卡面图是公开的游戏素材，不等于公开本局谁拿到哪张牌。资源 manifest 不能包含本局牌序、座位到手牌的映射或私密实例标识。

## 5. 权限与资源可见范围

本阶段仅 administrator 可创建/修改草稿、上传、校验、预览、发布、归档和请求删除；房主只选择已发布兼容版本。普通玩家不能借资源接口获得管理能力或任意文件路径。

默认发布的素材可供本平台所有已登录用户浏览/下载，草稿仅管理员可访问。使用同源鉴权资源服务，发布不代表匿名公开。不得把素材权限误当作私密游戏状态的保护：素材经授权下载后不能保证可收回，隐藏信息仍靠 View/事件投影。

管理员可预览完整静态牌组，但没有因此获得查看任意实际对局手牌的应用权限。预览必须用固定演示场景，不从真实对局读取完整 State。

已归档版本从新房选择器隐藏，已有引用对局仍能读取。普通玩家不因猜到 blob hash 或 fileId 而访问未发布草稿。

## 6. 资源契约与 manifest

每个游戏扩展声明 assetContractId/version/hash，列出必需与可选 key、image/audio 类型、参考比例、可见声音 cue。契约由可信游戏包提供，资源上传者无权扩大事件受众或新增规则事件。

参考结构，具体字段对齐仓库 schema：

```json
{
  "schemaVersion": 1,
  "packId": "color-match-paper",
  "version": "1.0.0",
  "gameId": "color-match",
  "assetContract": { "id": "color-match-assets", "version": "1" },
  "name": "纸张主题",
  "assets": {
    "card.red.1": { "kind": "image", "fileId": "validated-file-id-1" },
    "card.back.default": { "kind": "image", "fileId": "validated-file-id-2" },
    "sound.card.play": { "kind": "audio", "fileId": "validated-file-id-3" }
  },
  "sounds": {
    "card.played": { "assetKey": "sound.card.play", "gain": 0.7, "cooldownMs": 100 }
  }
}
```

示例不包含完整槽位，不能直接视为可发布完整包。fileId 是平台已校验对象引用，不允许 URL、绝对路径、脚本表达式或动态模板。文件物理路径/hash 由服务器生成，上传 manifest 不可信。

包版本标识发布后唯一且不可覆盖。显示名称可用中文，稳定 ID 使用受限 ASCII，拒绝重复 JSON key、危险对象键、未知可执行字段、深层嵌套和过长文本。manifest 文本按纯文本展示，不当 HTML。

兼容性通过游戏 ID + 精确资源契约版本验证，规则版本仍按原对局锁定。新增游戏资源要求时必须更新契约，不能只因文件 key 凑巧同名就宣称兼容。

## 7. 完整映射、缺失与版本依赖

本阶段发布物采用“展开后的完整 manifest”：所有必需图片槽位必须指向可用文件；可选音效缺失视为静音。允许管理员从已有版本复制草稿，复用文件引用，不要求重新上传全部素材。

不实现运行时多层继承或浮动 basePack/latest。若 UI 支持“沿用默认”，发布时解析到精确文件引用写入最终 manifest，使旧对局不受默认包更新影响。

校验报告区分阻止发布的错误与允许发布的提示。必需文件缺失、类型错误、损坏、契约不符、重复版本阻止发布；比例偏差等可作为提示。运行时偶发加载失败使用带文字的占位，不改变已锁定资源引用。

## 8. 文件类型、限制与处理

默认接受静态 PNG、JPEG、WebP 图片；短音频接受 MP3、PCM WAV。实际解码器/目标浏览器支持需开发时验证。首版拒绝 SVG、HTML、JS、CSS、可执行文件、视频、动画图、压缩包和外部链接导入，避免引入本阶段无需支持的运行能力。

参考可配置上限：单图 8 MiB、单边 4096 像素、总像素 1600 万；单音频 5 MiB、时长 10 秒、最多双声道；单包 200 文件、总上传字节 100 MiB；manifest 256 KiB。必须同时限制编码字节和解码后资源，不能仅检查扩展名。以上为首版容量默认，可按后续游戏调整。

执行 MIME/文件头/实际解码一致性检查。图片规范化可重编码、去 EXIF 等非必要元数据，并保存原始与处理后尺寸/hash 的对应；音频探测时长、采样率、声道与可解码性。规范化若改变字节，以最终被服务的文件 hash 为准。

媒体工具在低权限、无网络、有限 CPU/内存/运行时长的处理进程执行。服务端生成存储 key，不拼接用户文件名，不通过 shell 拼接任意路径。拒绝路径穿越、符号链接绕过、伪 MIME、超大解码图和损坏媒体。

原文件名仅用于管理显示；不把它当磁盘路径。重复内容可去重，但访问权限仍由文件引用和发布状态决定，不能因为同 hash 已公开就泄露其他草稿元信息。

## 9. 上传与校验流程

流程：创建草稿 → 上传到临时区 → 服务端探测/规范化 → 建立 validated 文件对象 → 更新映射 → 校验草稿 → 固定场景预览 → 发布。

上传入口沿用会话、Origin、CSRF、限流和角色检查；上传前预留配额，边接收边限制字节，不能先把无上限请求读入内存。客户端进度显示真实状态，取消上传不显示成功。

每个文件有 staged/processing/validated/failed 状态。processing 失败或进程重启可恢复/明确失败，不能留成“已可用”。多文件中一个失败不销毁此前成功文件，草稿可继续修复。

上传/发布支持 requestId 与内容一致性检查，重复点击不能复制多份版本；同请求 ID 不同内容拒绝。正文上传可采用 uploadSessionId，重传策略须明确，不要求分片断点续传。

媒体校验和文件写入不放在长数据库事务里；最终状态落库使用短事务。未通过校验的文件永远不能作为已发布运行资源。

## 10. 文件存储与数据库一致性

数据库保存元数据、清单、状态、引用和摘要；图片音频字节存文件目录/对象存储，不以 base64 塞进 matches 或 WS。

默认使用独立持久资源目录，通过存储接口提供 put/get/stat/delete；不写入应用容器可丢弃层、前端 public 源码目录或 Git。已有对象存储直接复用，不为本阶段强制迁移。服务端凭证不下发给客户端。

文件内容采用不可变 key；相同包/版本下不覆盖原字节。正式文件先写入并校验可读，再在发布事务中激活引用。数据库事务不能原子回滚对象存储，因此采用 staged + 引用保护 + 延迟清理处理孤儿文件，不能假称跨存储完全原子。

文件写成功、DB 提交失败只留下待清理孤儿，不能产生半发布版本；DB 已提交、响应丢失后由发布回执恢复相同版本。断电测试检查状态能收敛。

## 11. 草稿、发布、归档与删除

状态：draft → validating → ready → published → archived；校验失败回 draft 并保留错误。编辑草稿增加 draftRevision，旧校验报告和旧预览失效。

发布请求携带 requestId、expectedDraftRevision 和通过校验的 contentHash；事务再次确认草稿未变、文件 validated 且未待删除、契约有效、版本未占用，再写不可变 manifest 和发布回执。并发编辑与发布不能让未校验的新内容进入发布物。

published 不可原地编辑：复制为新版本草稿。归档只阻止新绑定，不影响已有对局和引用它的 waiting 房间启动；若需阻止新开局须另设明确 administrativelyBlocked 状态并告知房间，不能悄悄换包。

删除 published/archived 版本仅在没有 waiting 房间、任何保留对局、其他保留清单等引用时允许，默认优先归档。活动、结束、中止的历史对局仍算引用，直到将来明确删除对局。内置默认包不可删除。

物理文件删除为延迟 GC：事务标记 tombstone，拒绝新引用，复查引用后删除，失败可重试。正在上传/校验、预览短租约使用或发布过程中的文件需受保护。禁止“查一次引用为零→异步立刻删”与开局竞态造成丢文件。管理 UI 显示引用数量和不能删除的原因，不暴露他人私密对局内容。

## 12. 房间选择与开局锁定

房主在 waiting 房间选择已发布且兼容的精确 packVersion；变更沿用 roomRevision、请求去重和事务，清除真人 ready，脚本/模型 AI 就绪按原机制重新计算。普通成员只可查看选择结果，不替别人改包。

开局事务锁定 packVersionId、manifestHash、assetContractVersion，建立持久引用；与归档/删除状态检查使用一致锁序或等价原子约束。发布新版本不修改 waiting 或已开始房间的选择。

active 对局首版不换包。刷新和服务重启仍读取锁定版本，绝不自动改成最新版。默认包也必须拥有稳定版本。旧存档迁移只能映射到实际存在且内容可确认的旧默认资源，不伪造 hash；无法确认保留并报恢复阻塞。

某张图临时失败可占位，整包丢失报告资源不可用但保留游戏状态和真实绑定。平台仍可提供基于 View 的语义桌面/文字动作继续游戏，不静默选择另一资源包。

## 13. 资源读取、缓存与 URL

客户端通过资产解析器 resolveImage(key)/resolveSound(key) 获取当前锁定 manifest 的资源，不把自定义 URL 嵌进规则和 View。加载 manifest 也要有 schema/摘要一致性检查，不能把客户端缓存误认为权威版本。

同源鉴权服务返回正确 MIME、nosniff、长度及合理 ETag。不可变内容可以按授权模型缓存；本阶段默认 private 缓存，不把受认证访问的文件标 public 交给共享 CDN。未授权请求即便知道 ETag 也必须先鉴权，不能用 304 绕过授权。

若已有对象存储短时签名 URL，URL 过期不等于资源版本失效：重新鉴权获取 URL，不改 packVersion。签名 URL 不进入持久 manifest/事件/日志；本阶段默认不用直签则无需实现该分支。

读取接口不返回磁盘路径、bucket 凭证或上传临时区内容。退出账号清理私密游戏 View 和临时预览引用，但不宣称能收回此前合法下载的静态素材。

## 14. 游戏图片接入与可用性

Color Match 至少接入所有颜色数字卡面、统一牌背、公共区域背景和必要图标。用 View 中当前可见牌面 key 渲染本人手牌与公共牌；对手只按手牌数量画通用牌背。

隐藏牌不能在 DOM、alt、data 属性、CSS 背景 URL、预加载清单或无障碍标签里携带其真实牌面 key。允许预加载整套公开静态牌面，不允许依据对手实际手牌生成针对性预加载请求。牌背不因隐藏牌内容变化。

保留语义文字、颜色/数字与操作标签；图包不能删除合法目标提示、当前回合信息或点击区域。加载失败时显示“红色 3”等来自 View 的真实语义文字；对手隐藏牌只显示“牌背”。不靠图片中文字向规则/模型提供信息。

尺寸与 aspect-ratio 由组件和契约控制，避免布局跳动；长手牌区域在手机能滚动，不能整页横向溢出。解码/加载错误限制重试次数，不能每次 render 无限请求。

## 15. 游戏事件到声音 cue 的契约

先由服务端可信游戏扩展对内部事件做权限投影，再生成该接收者可用的表现 cue。资源包只将已经授权的 cue 映射成音频，不能自行检查完整 state 或改变受众。

契约声明 cueId、受众规则、是否可触发一次性表现、优先级/组等。Color Match 示例：card.played 的公共出牌音、card.drawn 的规则允许公开摸牌音、turn.started 的本人回合提示、match.finished 的结束音。若胜负音因本人身份不同，服务端投影或可信客户端通过本人公开结果派生，不能由上传表达式决定。

对私密操作，未授权玩家连 cue 类型、文件 key 和触发时间提示都不应收到。公开奖励数量与秘密选牌种类必须区分：允许公开“摸了一张”的游戏，只能发通用摸牌声，不得根据牌色选不同声音。没有信息权限测试覆盖的私密 cue 默认不开放资源映射。

声音来源分 game 与 ui：前者由已提交游戏事件触发，后者仅为本地按钮/界面提示。不能在“提交按钮按下”时播放成功出牌声，因为该动作可能失败。

## 16. 统一音频服务与用户控制

客户端应用共享一个音频管理服务，统一加载、播放、并发和清理；游戏组件通过 cue 请求播放，不自行随处 new Audio。具体选 Web Audio 或成熟等价实现由仓库决定，验证目标浏览器行为。

提供总静音、游戏音效音量、界面提示音音量和“启用声音/测试声音”。音量归一到 0–1，默认保守值如 game=0.5、ui=0.3；用户偏好可保存在 localStorage（仅偏好，无凭证/手牌），按账户隔离并跨刷新恢复。预览音量独立，不能修改对局设置。

没有用户交互授权时不强行播放，显示简洁启用入口；成功解锁之后只播放新的 live cue，不把之前积压事件补播。播放 promise 拒绝/AudioContext suspended 时安全降级，不影响规则与按钮。

静音立即停止正在播放的效果，音量调整影响当前与后续声音；解绑/切换对局、退出登录、关闭预览释放音源和监听。后台页面默认停止声音并丢弃后台期间表现，重新可见先同步，不补播。实际浏览器限制和未测试设备如实记录。

## 17. 去重、不补播与播放时限

事件沿用稳定 eventId=(matchId,revision,eventIndex)，每个投影 cue 另有 cueIndex；去重键至少包含 matchId/eventId/cueIndex。一次命令多个合法 cue 不应被 revision 粗暴合并。

只有当前已完成同步的连接世代中的新 live 事件允许表现。initial/resync/历史记录/重复 HTTP 回执不播放。恢复时由可信服务端/同步层确定快照覆盖的事件游标，客户端建立基线再启用 live 消费，不能只靠客户端时钟猜哪些是历史。

先标记消费或抑制，再异步加载/播放。静音、权限未启用、重复、过期或加载失败被丢弃的 cue 不排队等以后补播。默认 cue 等待加载最多 1 秒；到期后丢弃，即使文件稍后加载成功也不突然响。切换连接/对局后旧异步回调检查 generation，不能播放上一局声音。

内存去重集合须有界，但不能淘汰后让延迟老事件重新播放；结合快照游标/已关闭 revision 水位，或由协议保证每 revision 完整事件批次。同一 revision 可多事件时必须证明不会先提升水位导致合法后续 cue 丢失。将选择方案写入 ADR 并测试。

允许因网络丢失而少播声音，不允许为了补声音重放动作或阻塞状态同步。音效是尽力表现，不是结算确认。

## 18. 多标签页、叠加与资源预算

默认只在当前可见且获得音频主控权的标签页播放。用浏览器支持的协调机制选举同账户同对局的音频 owner；有多个可见窗口时也避免一事件双响。主控切换先同步并建立游标，不接手旧播放队列。能力不足时明确保守降级为需用户手动启用当前页，不假称全浏览器唯一播放已实现。

参考限制：全局最多 8 个同时音源，同一 cue/组最多 2 个；出牌高频 cue 有冷却，结束提示有较高优先级。已抑制事件算消费，不稍后补播。限制来自平台上限，资源包不能填极高并发/音量绕过。

每包图片总字节和已解码音频缓存有上限；音频仅按需/有限预加载，LRU 回收不再使用 buffer，卸载对局释放无用资源。音效峰值可检测并提示过响，不允许超大 gain；不以长时间循环实现背景音乐。

## 19. 管理页面与预览体验

管理端至少有资源包列表、草稿编辑页、文件上传列表、映射表、校验报告、固定场景预览和发布/归档操作。表单优先，JSON 导入可用，暂不开发拖拽式全能编辑器。

映射表按契约列出全部槽位、必需/可选、当前文件、类型、尺寸/时长和错误。选择文件有缩略图/主动试听；不要自动播放每个上传音频。表单编辑和 JSON 导入共用同一 schema，保存不可丢失未改字段。

预览包含本人手牌、对手牌背、公共牌、选中/禁用/缺图状态和音效按钮。使用假演示数据，显著标明预览，不连接真实对局。预览声音只在用户点击时触发，并与正式事件通道隔离。

发布前展示包 ID、版本、兼容契约、文件数、总大小和校验结果。删除要求显示影响及确认，引用中只能归档。管理功能 desktop 优先但窄屏应可读可滚动；普通玩家的包选择与音量操作必须在手机可用。

## 20. 两套演示资源与版权记录

交付 Color Match 的默认包与一套明显不同的替换包，至少卡面、牌背、背景和数个短音效不同，证明替换真实生效。可用原创简单几何设计、程序合成短提示音或明确可用的开放素材；不要求 AI 生成图片，更不把商业图包作为验收前提。

每包保留作者、来源与许可说明字段/NOTICE 文件；自制素材说明生成方法，开放素材记录原始来源和署名要求。不下载或复制商业游戏整套素材来完成任务书。

图包颜色样式变化不能改变逻辑红/蓝/数字的语义含义，保留可辨认的颜色标签或符号。演示音效采用短、适中响度，提供静音下全部可完成的操作。

## 22. 异常、运维与恢复

| 故障 | 应有行为 |
| --- | --- |
| 上传中断/配额不足 | 明确失败或可重试，不能成为有效文件 |
| 媒体探测进程超时 | 有界终止，草稿可修复，不拖垮 API |
| 发布提交前失败 | 没有半发布版本，孤儿按延迟清理 |
| 发布成功响应丢失 | 原 requestId 返回同版本 |
| 文件服务暂不可用 | 图片占位、声音静音，游戏继续 |
| manifest/hash 不匹配 | 拒绝用错误清单，保留真实绑定并提示 |
| 音频解锁/播放失败 | 简洁提示，状态更新与操作不受阻 |
| 旧异步请求晚到 | generation 检查后丢弃，不串局 |
| 重启 | 已发布文件/引用仍在，处理任务恢复或安全失败 |
| 删除中崩溃 | 重试可恢复，不删除仍受引用保护的文件 |

README 写明资源目录持久卷、权限、磁盘配额和备份恢复要同时包含 DB 与资源。提供导出清单/完整性检查命令：统计丢失 hash、不可读文件与孤儿；默认只报告，删除需明确操作。首次实现本地存储，不宣称具备 CDN 全球加速或完整灾备。

## 24. 测试方法

真实数据库与真实持久文件目录验证上传/发布/引用，使用独立连接和测试屏障验证发布时编辑、删除时开局。进程重启后检查文件仍可读，而非只检查数据库记录存在。

用两独立浏览器账户与非成员/非管理员账户验证资源管理、私密 View 与 cue。检查网络、DOM、alt、缓存 key 和预加载，不只截图。测试全部素材公开时仍不能推出对手实际手牌映射。

声音测试分两层：自动测试通过 spy/受控时钟断言播放调用次数、音量、取消和去重；真实浏览器手动验证实际可听、静音、用户解锁及重连无补播。仅 mock AudioContext 通过不代表真机可播放；无法测试 iOS 实机时如实标未测，并用可用 WebKit 环境做补充但不冒称实机。

音效链路回归无需重复付费调用大模型，使用原有 mock/脚本验证同样事件源即可；只有发现具体模型回归风险才追加有授权的有限联调。
