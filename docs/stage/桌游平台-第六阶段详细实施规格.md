# 桌游平台：第六阶段详细实施规格

版本：1.0  
日期：2026-09-25  
阶段：十阶段计划的阶段 6——大模型 AI 与个人模型配置

## 1. 执行前提与文档关系

用户已确认第五阶段完成。本任务书衔接已有脚本 AI、控制权 epoch、持久任务、冻结提案、统一命令事务和恢复机制。编写时已读取第五阶段任务书，未检查实际仓库，也不声称已验收代码。执行者必须先核对仓库现状。

沿用原有技术栈、账户系统、PostgreSQL、游戏 SDK、Color Match 规则和前端组件。新增可替换的模型决策适配器，不另造模型专用游戏逻辑或调度系统。命名与数字是实施默认值，等价实现可复用，偏差记录到 docs/decisions.md。

本规格定义项目自身契约，不保证任何供应商当前接口、模型名称、价格或结构化输出能力。落地具体适配器时，执行者须核对所选供应商官方文档与仓库 SDK 版本，记录核对日期、支持范围和限制；不要根据本文件猜测外部 API 参数。

## 2. 阶段目标与可演示成果

每位用户可在个人设置中保存自己的模型配置和凭证，选择模型接管自己的座位；房主可使用自己的配置创建专用模型 AI。不同座位可以分别由真人、脚本 AI 或不同模型控制。

完成后的演示：真人与真实模型完整玩一局；模型看到的只有自己的合法视图；非法输出经过有限修复后由脚本兜底；断网、限流、超时或预算耗尽时对局仍能继续；收回控制后旧模型结果失效；服务重启不重复提交已确认动作。

**可靠参与是验收重点，不要求模型达到高手水平。** 不把联网成功、返回一段文字或全部动作均由兜底完成，冒充真实模型完成了玩法验证。

## 5. 配置、凭证、控制器与付款责任

必须区分以下对象：

| 对象 | 职责 |
| --- | --- |
| ProviderEndpoint | 管理员允许访问的模型服务地址与协议类型 |
| PersonalModelProfile | 某用户的模型名、参数、端点引用、输出模式等非秘密配置 |
| Credential | 该用户的加密 API 凭证及撤销版本 |
| ModelBinding | 某局某席位使用的配置快照、凭证授权、预算与 fallback |
| ModelAttempt | 一次可能产生外部费用的调用尝试 |
| GameCommand | 最终提交游戏动作的幂等命令 |

真人只能绑定自己的 profile；房主为专用 AI 绑定自己的 profile。本阶段不做跨用户凭证分享、不允许房主选择别人的 profileId、不把“我是管理员”视为普通应用中的任意解密权。

专用 AI 的 credentialOwnerAccountId 固定，不随房主转移而改变。房主转移不转移凭证或费用责任；原凭证所有者仍可撤销授权，新房主只能关闭对局或将专用 AI 切到已安装脚本，不能继续使用未经授权的新凭证。中途给专用 AI 换另一人的付费配置留到后续；修复端点和明确重新授权原配置可提供受控入口。

不自动使用平台公共密钥填补用户密钥错误。若部署者显式启用公共配置，需独立权限和额度；本阶段默认关闭。

## 6. 个人模型配置页面与生命周期

个人设置提供：名称、允许的服务端点、模型标识、支持的参数、API key 写入、测试连接、默认预算、启用/禁用、替换 key、撤销/删除。模型名可手填或从显式列表选择，不要求所有供应商都支持列模型接口。

保存配置不发付费推理请求。测试连接是用户明确点击的独立操作，提示可能调用 API，并使用单独小额度、限流与 attempt 记录；优先无私密内容的最小结构化输出测试，不发送当前对局或手牌。

读取接口只返回 hasCredential、状态和非秘密配置，不返回解密 key；UI 不把空输入当作删除，替换/保留/撤销使用明确字段。保存后清空 key 输入，不能放入 localStorage、sessionStorage、URL 或分析埋点。

每次修改非秘密推理配置生成新的 immutable profileVersion；已绑定对局继续使用旧快照，避免修改个人默认项悄悄改变正在进行的对局。端点变更不能把旧 key 自动发送到新地址，必须重新确认并绑定对应凭证。

撤销 credential/授权立即阻止后续新调用，并通过授权版本校验拒绝尚未提交的旧模型结果；已完成的游戏动作和已产生的外部费用不回滚。profile 删除采用禁用/软删除，保留必要审计引用，不破坏历史回执。

## 7. 密钥保存与服务端边界

所有外部调用由服务器执行。浏览器只向本平台 HTTPS 接口提交 key，平台不把 key 下发给游戏客户端、扩展 UI、WS、日志或任务 payload。

使用成熟密码库的认证加密保存凭证；每条记录使用唯一 nonce，保存算法/keyVersion/必要认证信息，并把 owner/credential ID 绑定为关联数据。主加密密钥由环境或部署 secret 提供，与数据库备份分离；禁止硬编码、放 Git、默认开发万能密钥或自制加密算法。

解密仅在已授权调用前发生，传给适配器的秘密不进入 DTO 和通用日志。采用最小作用域，避免长时间缓存；不宣称能可靠擦除托管语言内存。无法解密或主密钥缺失时，模型功能明确不可用，不能把全部网站或脚本 AI 一起弄崩。

文档需说明数据库备份恢复需要相应密钥版本，给出可操作的密钥轮换流程及失败保护。控制台异常脱敏不应仅依赖“截掉 key 最后几位”，任何 Authorization header 和原始供应商错误体默认禁止记录。

## 8. 自定义 API 地址与网络访问策略

用户可以使用自定义服务，但运行时只允许选择管理员批准的 ProviderEndpoint；个人配置不能提供任意运行时 URL。这保留自建/兼容服务能力，也避免把平台服务器变成任意内网请求代理。

默认端点只允许 HTTPS，固定协议、host、port、basePath；禁止 URL 用户名密码、片段、动态重定向和用户指定代理/header 模板。TLS 校验保持开启。SDK 自动 follow redirect 必须关闭，不向重定向目标转发 key。

在端点注册和每次连接时校验目标，处理 IPv4/IPv6、localhost、回环、私有地址、链路本地、云元数据及其他不可公开路由范围。DNS 校验必须与实际连接地址绑定，防止先查公网、连接时改解析到内网；仅字符串检查域名不合格。使用成熟网络组件或受控出口网关，实现不了则默认仅允许固定官方端点，并明确自定义地址未完成。

部署者确需本机模型时，通过单独管理员配置启用精确地址/端口的私网例外，限制目标与凭证，不允许普通用户开启“允许所有内网”。本阶段不强制支持本机模型。

连接探测与真实决策必须走同一个出口策略。测试 fake provider 的地址通过测试环境注入，不能为测试永久关闭生产检查。

## 9. 可替换适配器与能力声明

最少交付一个真实协议适配器和 mock 适配器；优先选择仓库最容易可靠集成的一种明确协议。若采用兼容协议，只声明实际测过的能力，不承诺所有标称兼容服务都支持同样参数。另一厂商原生协议按真实需求追加，不把不同协议只改 base URL 冒充适配完成。

适配器职责：构造供应商请求、处理认证、超时、输出约束、响应解析和用量归一化。平台统一负责权限、预算、任务、候选映射和动作提交。以下是内部伪接口，不是供应商 API：

```ts
type ModelResult = {
  outputText: string;
  providerRequestId?: string;
  returnedModelId?: string;
  usage: {
    inputTokens: number | null;
    outputTokens: number | null;
    cachedInputTokens?: number | null;
    reasoningTokens?: number | null;
  };
  finishReason: string;
};
```

显式声明 schema/json/text 输出能力、可配置参数、usage 可用性、取消能力与模型上下文限制。只发送已支持参数，禁止将未知配置透传给供应商。失败类型归一化：auth、rate_limit、unavailable、timeout、invalid_output、refusal、context_limit、transport_unknown。

本阶段非流式决策足够；不用向玩家流式输出模型文本。禁止自动执行模型工具调用、访问网页或数据库，模型仅选择允许的桌游动作。

## 10. 玩家视图、规则摘要和提示词

模型输入来自游戏扩展提供的版本化 aiDescriptor：规则摘要、动作解释、胜利目标和 phase 语义。摘要必须与已验收规则一致，覆盖数字 5 的目标选择等机制，不能由平台核心写死 Color Match 特判。

每次决策只包含当前 seat 的 View、公开必要历史、当前 phase、候选动作与明确输出要求。使用稳定 seat 标签替代账户邮箱/用户名；不发送 session、凭证、牌堆顺序、其他人手牌或完整 State。候选、描述与 View 来自同一 revision。

默认每次独立请求，不共享多个座位的对话历史、线程 ID 或模型记忆。即使两个 AI 使用同一 key，也要按 match/seat/epoch 隔离上下文；不得把 A 的历史提示词给 B 复用。

昵称、游戏文本和历史记录当作数据，而非高权限指令；限制长度，不让“忽略规则”等文本改变输出协议。Prompt 不是权限边界，动作验证才是。不开聊天输入、本阶段不开放任意用户系统提示词编辑。

token 超限时先删减可选公开历史，不截掉自己的必要手牌、合法候选或规则到产生错误语义。仍放不下则停止该次模型调用并脚本兜底；不得发送不完整候选却宣称模型拥有完整选择。

## 11. 结构化动作：优先使用候选 ID

Color Match 候选少，本阶段默认由服务器为当前任务生成稳定映射：

```json
{
  "decisionId": "opaque-decision-id",
  "choices": [
    { "id": "a1", "description": "打出自己手中的红色 3" },
    { "id": "a2", "description": "摸牌" }
  ]
}
```

示例仅说明格式，实际 candidates 由规则生成，不保证两种动作在所有局面同时合法。模型返回：

```json
{ "decisionId": "opaque-decision-id", "choiceId": "a1" }
```

服务端检查精确 schema、字段类型、额外字段、decisionId 和 choiceId，再将 ID 映射为真正 action。模型不能自创 cardId、seatId、requestId、revision 或 actor。映射只对该 task/revision/epoch 有效，不能把旧 a1 当新局面的 a1。

支持原生 schema 时使用；仅文本时严格解析一个 JSON 对象。允许的兼容处理须有限且可测试，例如明确剥离一层完整代码围栏；不能从任意长文本贪婪提取第一个大括号然后当命令执行。拒绝截断、多个对象、未知 ID、超长输出和工具调用。

选择 ID 映射不是最终授权。冻结前、提交前仍校验当前控制、授权、revision 和合法性。未来复杂动作空间可扩展参数 schema，本阶段不做万能 JSON 表单或任意工具执行器。

## 12. 有限修复与脚本兜底

默认一个决策最多两次外部调用：首次调用，再最多一次修复或传输重试；两者共享上限，不叠加成无限尝试。每次实际发送都单独记录、预留预算，SDK 隐式重试关闭。

结构/选择错误且有预算与剩余时间时，可发一次修复请求：给出同一安全上下文和简短验证错误，不附完整服务器异常。拒绝回答、认证失败、模型不支持、预算耗尽、上下文过长或外部结果未知默认直接脚本兜底，避免反复烧额度。

限流/暂时错误只在供应商语义明确、剩余时间足够且尚未用掉第二次机会时有限退避；遵守合理 Retry-After，不超出决策总时限。

所有模型结果在冻结前与 fallback 竞争同一原子决策槽位，只能有一个最终提案。模型迟到后不能覆盖已冻结脚本提案；已冻结模型动作的游戏提交结果未知时，不得另跑脚本重复操作。

fallback 使用第五阶段同一座位安全输入和合法策略，记录 decisionSource=model|script_fallback|mock。公开 UI 简要显示本次降级及安全原因，不能把脚本结果标成模型选择。

## 13. 时间、并发与租约

参考默认值：连接超时 5 秒，单次请求最多 20 秒，一次决策从开始计算起总时限 45 秒（包含重试/修复，排队另计）；输入预算默认 8k tokens、输出上限默认 512 tokens。不同模型能力可能要求调整，超出部署上限不能仅靠用户填写突破。

模型任务租约需覆盖网络执行，默认 60 秒并每 10 秒续租；续租以 leaseGeneration 条件更新，失去租约立即停止新调用/提交。不得继续用脚本任务的 15 秒 lease 导致正常调用被重复领取。脚本与模型可有独立执行槽，避免慢 API 占满脚本兜底资源。

默认全局外部并发 4，每凭证 1、每局 1；真实吞吐以配置和供应商限制为准。排队公平，设最长排队时间（默认 60 秒），超出可降级脚本并明确原因。已有进行中的远端调用取消后仍可能计费；已知仍在进行时保留相应 in-flight 记录至终止或截止，不把取消当释放所有费用风险。

账户/配置/端点维度限流；测试连接也受限制。可添加小型端点熔断，防止故障期间每回合都重复尝试。禁止在数据库事务中等待网络、退避或执行模型。

## 14. 预算、预留与用量：不能只在调用后相加

预算至少包含：每决策最多调用数、每局每付款人的最大外部调用数、每用户每日调用数、单次输入/输出上限；可加估算货币预算。部署提供有限的默认额度，用户须显式启用实际付费模型，不自动开始探测或长时间测试。

对相同 key 多配置、同付款人多席位和多房间进行原子预算预留。可用带服务器秘密的凭证指纹归并并发/额度，不保存可公开查询的裸 key hash。每次外部 attempt 在发送前事务锁定相应预算桶，确认剩余额度并建立唯一 reservation，提交后再发送。

调用结束后按 usage 一次性结算 reservation，重复响应/回调不重复计费。预算桶的锁序必须固定，不能与 room/match/task 形成反向等待；不持有任何预算锁跨网络。发送前复查任务授权，未发送即失效可释放预留。

usage 缺失为 null/unknown，不能写 0。可获得的缓存/推理 token 按适配器语义记录，避免与 outputTokens 重复累计。报价配置带币种、来源、更新时间和版本，不硬编码当前价格，不声称本地估算等于供应商账单。

对已发出但未知是否完成的请求，保守保留该次调用和估算上限的占用，后续人工/供应商记录对账；不能因为超时或重启退还全部预算。只有能证明未发送的尝试才直接释放。

金额硬上限仅在能可靠保守估算输入及所有可计费输出时启用；否则 UI 明确“估算费用”，以调用次数与输出限制控制本平台新请求，并建议部署者结合供应商自身额度。未知单价不能显示为免费，也不能保证绝不超出外部实际账单。

达到任何预算后不再发请求，切脚本继续；每局预算不因 API 重启、重新托管、手动重试、换同付款人配置或轮换 key 自动清零。日额度按明确时区边界记录，本项目默认 Asia/Shanghai，可部署配置。

## 15. 外部调用与游戏命令是两类不同的幂等

游戏 command requestId 保证同一已冻结动作最多提交一次。外部 modelAttemptId 用于记录可能收费的调用，不能假定供应商支持它作为幂等键；只有官方确认且适配器实际实现时才使用供应商幂等功能。

调用状态建议：reserved → dispatching → completed/failed/unknown/cancelled；外部 response 与本地持久化之间存在不可消除的崩溃窗口，不能承诺外部调用 exactly-once。

恢复规则：

- reserved 且可靠证明尚未开始发送，可继续发送或释放。
- dispatching 后崩溃，无法证明未发送，记 unknown；默认不自动重发该 attempt，原决策可转脚本兜底。
- response 已安全解析并持久化 accepted choice，可继续冻结，不再调用模型。
- proposed 已冻结，沿用原 action/requestId 提交；先查游戏回执再恢复。
- 晚到响应可以补 usage 结算，但不得替换已失效决策或已有提案。

每次“明确的新外部重试”都产生新的 attemptId 并占额度；不为了恢复好看而把多次真实请求合并成一条零费用日志。

## 16. 托管、撤销与凭证授权版本

扩展 controllerType=human|script|model。human→model、script→model、model→human、model→script 或变更绑定时，依照第五阶段控制事务递增 epoch；保留所有权与真人查看本人手牌权限。正常一次模型失败使用脚本兜底不改变长期 controllerType，只记录该次 decisionSource。

真人收回仍在短事务中完成，不等外部请求返回。旧结果在冻结/提交时检查 controllerEpoch、sourceRevision、leaseGeneration、bindingVersion 和 credentialAuthorizationVersion。即使撤销消息/AbortSignal 丢失，仍不能提交旧结果。

撤销凭证采用独立、持久授权版本；不必逐个同步修改所有对局才能阻止新请求，但最终提交必须验证授权。账户停用同时阻止其自己座位的自动行动及其资助的专用模型新调用。专用 AI 可降级脚本继续，停用账户的真人席位按第五阶段等待策略处理。

普通登出、会话过期、密码重置不自动撤销已有后台托管授权，UI 明确说明；提供“停用此模型配置/撤销凭证”以停止新模型调用。已向外部发出的请求无法保证撤回或免收费。

## 17. 配置锁定与供应商模型变更

绑定固定 profileVersion、adapterVersion、promptVersion、outputSchemaVersion、fallbackPolicyVersion，以及模型标识和相关参数快照。任务引用这些版本，修改默认配置不影响旧任务。

模型供应商可能让同一别名指向更新后的模型，本平台不能仅凭字符串保证模型行为永久不变。若有可用快照标识可选择并记录，响应提供 returnedModelId 时保存；不承诺云模型可完全复现。游戏规则、随机源、命令和已冻结提案仍必须可恢复。

认证凭证与端点绑定，凭证轮换是明确授权变更；新的未发送任务可按记录的新授权重新绑定，旧 in-flight 结果失效并降级/重建决策。不能把撤销旧授权的结果偷偷当新授权结果接受。所有显式重新启用仍计入同一局预算。

## 20. UI 与外部数据发送说明

个人设置清楚区分“脚本 AI”“真实模型”“模拟模型”。保存不等于测试通过，测试通过不等于所有功能长期可用；显示测试时间和所测能力，不只给一个永久绿勾。

首次模型绑定说明：该座位允许看到的手牌/局面会发送到所选服务，可能产生 API 费用；显示本局调用上限、估算费用状态、超时/预算耗尽转脚本策略。授权通过实际“启用模型”动作持久记录，不在每回合重复弹确认。

房间允许不同人独立设置本人托管；房主不能替真人设置模型。专用 AI 显示费用由配置所有者承担，转移房主不改变。模型断线时给安全提示和脚本降级状态；本人始终可收回，按钮不被“调用中”锁死。

费用展示分已报告 usage、待确认占用和估算费用，不把 unknown 填成 0。API key 输入不回显保存值，模型响应以安全纯文本处理，不渲染 HTML。本阶段不显示完整思考过程或原始提示词。

## 21. 模拟适配器与真实验收

mock 不联网、不读取真实 key，必须在 UI、日志和验收中标注模拟。提供成功、非法 choice、格式错误、超时、拒绝、限流、usage 缺失、超大响应、迟到结果等可控行为。

本地 fake provider 用真实 HTTP 协议测试请求/响应、超时、取消与错误转换；不等于真实供应商验收。生产不会自动因为没有 key 而把 mock 伪装成正常模型。

真实验收需用户已配置并授权使用的服务和有限预算；不得扫描其他目录/环境捞取无关 key，也不在聊天中要求用户公开粘贴密钥。优先使用设置页或已有授权 secret 注入。

真实测试至少完成一局 Color Match，记录模型产生并成功提交的动作数、fallback 数、总调用、耗时与可得 usage。须证明出牌/摸牌/目标选择中实际遇到的模型动作路径；未自然覆盖的 phase 可用合法 fixture 单独验证。全部动作由脚本完成不算真实模型通过。

缺少真实环境时交付其余实现，标记“真实供应商联调未执行/阻塞”和具体复现步骤，不捏造通过记录。不要为追求胜率进行大量付费跑分。

## 22. 异常与恢复矩阵

| 情况 | 处理 |
| --- | --- |
| key 错误/权限不足 | 停止该配置新调用，明确凭证错误，脚本降级 |
| 429/服务临时失败 | 剩余调用/时间预算内有限重试，否则兜底 |
| 超时/响应未知 | 保守记账，不自动重复发送未知请求，兜底 |
| 非法 JSON/候选 ID | 最多一次修复，仍失败兜底 |
| 拒绝/上下文超限/不支持 schema | 明确能力或输出错误，不无限修复 |
| 预算耗尽 | 不再联网，脚本继续 |
| 用户收回/凭证撤销 | 取消最佳努力，旧结果不可提交 |
| API 重启但请求可能发出 | attempt unknown，保留占用并按恢复策略处理 |
| DB 故障 | 不创建未持久预算请求，不接受内存假成功 |
| fallback 也失败 | blocked，沿用第五阶段恢复入口 |

降级不修改游戏规则、不把模型错误算玩家输、不新增跳回合特权。供应商错误信息脱敏后归一化，不将原错误 body 原样转给前端。

## 23. 日志、用量保留与诊断

默认记录 task/attempt ID、adapter/profile 版本、模型标识、输入大小估计、输出大小、latency、usage、重试/修复次数、fallback 原因及提交结果。日志不记录 key、Authorization、完整 prompt/response、手牌或候选列表。

原始模型响应仅在解析所需内存中短暂存在；默认不长期保存。用于恢复的已验证 choice/proposal 是私密业务数据，权限沿用任务表。外部错误体不得进入公开 tracing 系统。

诊断界面给用户看“调用超时”“预算已用完”“返回格式不符合要求”等，不显示服务端堆栈。保留 attempt 与预算记录到本局审计周期结束，不能过早清理导致重启重计或预算清零。

## 25. 验收测试方法

真实 PostgreSQL 验证预算事务与命令回执；不同 browser contexts 验证配置所有权。fake provider 记录实际收到的请求次数和 body，并在测试环境检查其中没有禁止字段；不要把带手牌的抓包提交到公共报告。

用屏障控制：预留后发送前、dispatching 后远端处理时、响应后持久化前、提案冻结后、游戏 COMMIT 后、撤销授权与响应竞争。真实终止 API/worker 验证恢复，不只 mock 状态变量。

对提示词做隐藏信息差分：两份状态有相同本人 View/公开信息但不同隐藏信息，生成的模型请求正文应相同（排除随机 trace 标识）；不要要求非确定性云模型必然返回相同文字。

计费测试使用模拟单价和 usage，覆盖缺失、缓存、推理 token、重复回调、超时未知和并发；不能拿过时真实价格写死快照。
