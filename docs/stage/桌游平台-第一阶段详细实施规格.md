## 2. 项目完整目标

建设一个浏览器在线桌游平台，最初面向私人邀请、小规模、自部署使用。平台负责账户、房间、座位、联机、权限、存档、资源与 AI 调度；游戏扩展负责规则、内容、玩家可见信息、操作、界面和表现。

最终需要支持：

- 开发者通过代码高度自定义规则、卡牌、棋盘、操作和布局。
- 图片与音效独立替换，不能因换图或换声音改变规则。
- 真人与 AI 同局游玩，支持脚本 AI、大模型 AI、主动托管和收回控制。
- 轮流行动、同时秘密选择、资源结算、空间放置等不同机制。
- 后续能单独重做前端，不重写规则和通信。
- 桌面和手机浏览器；拖拽操作有点选替代。
- 服务端权威状态和玩家私密视图；浏览器不能收到全量状态再自行隐藏。
- 游戏与资源版本锁定，刷新、断网和重启后恢复。

游戏例子 UNO、波多黎各、方舟动物园说明机制跨度，不是本阶段开发清单。正式首版使用原创示例 Color Match 和 Grid Garden；不自动下载未经授权的商业素材。

## 3. 第一阶段完成后应看到什么

1. 开发者按 README 启动 PostgreSQL、API 和网页。
2. 首页显示项目名称、来自真实 API 的已注册扩展列表。
3. 状态页显示 HTTP、数据库就绪情况，并能进行 WebSocket ping/pong 检查。
4. 开发环境中的“扩展实验台”能够启动一个两座位测试游戏，操作后看到服务端计算的视图。
5. 实验台能切换测试座位检查信息投影；切换仅属于开发工具，不是生产身份机制。
6. 测试游戏可以结束和重新开始；非法动作明确失败。
7. 构建、类型检查、关键测试通过，有实际运行记录。
8. 生产配置关闭实验台和开发接口，不暴露秘密状态和假身份入口。

## 5. 开发前检查

Codex 应先查看当前目录、Git 状态、AGENTS.md、已有 package.json 和项目说明。存在项目时沿用可用结构，不直接覆盖；记录实施范围内已有修改并保留。空目录可以初始化，不猜测远程仓库或服务器路径。

检查 Node、pnpm、Docker、PostgreSQL 可用性。选择运行环境支持的稳定兼容版本并锁定，记录实测版本。不要虚构“最新版本”；遇到依赖 API 不确定时查对应官方文档。缺少 Docker 可使用明确配置的本地 PostgreSQL，不以 SQLite 或内存数据库替代真实数据库验收。

缺少依赖安装网络或数据库权限时，完成能够实施的部分并准确标记阻塞，不伪造通过。不要读取、输出或提交其他项目凭据。

### 7.1 导入方向

- web → client-sdk、protocol、ui、游戏 client/shared。
- api → protocol、game-sdk、数据库模块；装配层可导入游戏 server。
- 游戏 server → game-sdk、自身 shared，不能导入 React、数据库、HTTP 或模型 SDK。
- 游戏 client → 自身 shared、ui、game-sdk 的浏览器安全类型；不能导入 server。
- protocol 和 game-sdk 的共享入口不能依赖 apps。
- 前端与后端分别显式注册同一扩展 ID/版本，不从服务器收到路径后动态执行任意 URL。

通过 package exports 和静态依赖检查禁止 server 入口进入前端。不要建立 re-export 所有服务端和客户端内容的总入口。仅靠目录名不是隔离。

## 8. 命名、标识与基础类型

项目内部默认名称 boardgame-platform，显示名称“桌游平台”，以后可改。

- gameId 使用命名空间式稳定标识，如 demo.test-counter。
- 扩展版本、内容版本、资源版本分开；首个测试版本使用 0.1.0。
- SDK 初版兼容范围显式声明；加载不兼容版本必须拒绝。
- accountId、roomId、seatId、matchId、connectionId 在语义上不同，正式实体 ID 由服务端生成。
- requestId 是一次动作意图的 ID；重试保留 ID，新动作生成新 ID。
- revision 是非负安全整数，仅成功状态转换递增；非法动作不递增。
- eventId 在一次已提交转换内唯一，默认由 matchId、revision、事件序号生成。
- JSON 值只允许 null、布尔、有限数值、字符串、数组和普通对象。不允许 undefined、NaN、Infinity、BigInt、函数、循环引用及未编码 Date/Map/Set。
- 网络时间字段采用 UTC ISO 字符串；游戏规则不直接读取系统时间。

## 9. 游戏扩展 manifest

本阶段实际实现 manifest schema 与注册校验。建议结构：

```json
{
  "id": "demo.test-counter",
  "version": "0.1.0",
  "sdkRange": "^0.1.0",
  "contentVersion": "0.1.0",
  "name": "计数测试游戏",
  "description": "仅用于扩展接口验收",
  "players": { "min": 2, "max": 2 },
  "mode": "rules-driven",
  "capabilities": ["private-view", "turn-based"],
  "defaultAssetPack": { "id": "demo.counter-assets", "version": "0.1.0" },
  "developmentOnly": true
}
```

capabilities 是描述，不让核心以此硬编码玩法。新增扩展能力可以演进枚举；本阶段明确支持值与未知值的处理。选项由独立 options schema 校验，本示例只允许 targetScore，默认 3，整数范围 2–10。

重复注册同一 ID/版本、人数上下界错误、无服务端实现、SDK 不兼容，都应启动失败并输出可定位错误。测试扩展在生产配置下不注册；扩展列表为空是正常状态。

服务器注册表保存规则实现，数据库保存安装元信息；不能仅因为数据库有一行记录就认为扩展可执行。就绪检查确认代码注册表与启用安装记录匹配。

## 10. SDK：第一阶段必须落地的接口

下表是语义契约，Codex 必须提供对应 TypeScript 接口、schema 和可运行示例。接口名可微调，但职责不可省略。

| 接口 | 输入 | 输出与限制 |
| --- | --- | --- |
| validateOptions | unknown | 合法 Options 或安全错误 |
| setup | seats、options、受控随机源 | 完整 State；不包含网络调用 |
| getView | State、Viewer | 此身份的 View；无权限则失败 |
| getActionSpec | State、Viewer | 当前可用动作及参数约束；仅可见信息 |
| validateAction | State、可信 Actor、已解析 Action | 合法或业务拒绝；不能只信客户端合法动作列表 |
| applyAction | State、Actor、Action、规则上下文 | 新 State 与内部事件；不得改变旧状态 |
| projectEvents | 内部事件、Viewer | 可发送事件列表，无隐藏字段 |
| getOutcome | State | ongoing 或 finished；得分和赢家用 seatId |
| serialize | State | JSON 存档值，不包含可执行代码 |
| deserialize | 版本信息、unknown | 校验后的 State；不兼容版本拒绝 |
| getFallbackAction | 玩家 View、动作描述 | Action 或 null；仍须服务端校验 |

所有规则函数在此阶段默认同步；昂贵搜索和模型调用不属于规则执行。View 是便于 UI/AI 使用的独立类型，不是 State 的简单删字段副本。内部事件和公开事件也是不同类型。

### 10.1 操作描述

通用动作 envelope 使用 type 和 payload；每个游戏拥有自己的 discriminated union/schema。本阶段示例动作只有 add，payload 为 value，允许 1 或 2。

getActionSpec 返回可序列化描述：动作类型、标题、参数约束、是否当前可用。示例可以使用 enum 表达 value 的合法值。未来允许按需查询合法目标；现在不实现万能动态表单或完整 JSON Schema 解释器。

### 10.2 随机与可重现

游戏只通过注入的 rng.nextInt(minInclusive, maxExclusive) 获取随机值。需实现算法及状态可序列化的确定性 RNG，并记录算法版本；初始种子由运行器产生。测试传固定种子。RNG 不是账号 token 或邀请码生成器。

runner 每次转换使用克隆后的状态和 RNG 状态，验证失败或执行失败不提交任何变化。序列化样例包含游戏状态与 RNG 状态，但只能留在服务端测试或存档中。

### 10.3 可信身份

Actor 来自服务端鉴权/控制器映射，不能从动作 payload 取可信 role 或 accountId。测试实验台的 seat 选择由独立开发路由适配，不能成为正式 runner 的认证方式。尚未实现生产身份时，正式对局路由不注册。

## 11. 原创测试扩展 Test Counter

该游戏只用于验证 SDK，不代替阶段 3 的 Color Match。

### 11.1 完整规则

- 固定两个座位，按输入顺序轮流行动，第一个先行动。
- 两人初始分数为 0，目标分数默认 3，可配置 2–10。
- 开局为每个座位分配一个私密整数提示码，范围 0–999999，用于测试信息隔离，不参与胜负。
- 当前玩家可选择 add，value 为 1 或 2，加到自己分数。
- 分数达到或超过目标立即获胜并结束；否则轮到另一人。
- 非当前玩家、非法 value、额外未知字段、结束后的动作均拒绝。
- 不支持跳过、撤销或中途更改选项。
- 重开创建新的实验台 matchId，不复用旧对局。

### 11.2 状态和视图

State 包含 seats、scores、activeSeatId、targetScore、privateHints、outcome。View 包含公开分数、目标、当前座位、结果和 viewingSeatId 对应的 myHint。其他人的提示码必须在响应序列化之前移除，不能以 hidden=true 保留。

setup 产生一次公开 started 事件及两条分别仅该座位可见的 hint.assigned 事件。add 产生公开 counter.added 事件；结束时再产生 counter.finished。每条事件携带正确可见范围，私密事件投影不能泄露他人 seat 对应的提示值。

浏览器开发实验台允许主动切换到另一测试身份，因此不是安全的多人产品；信息隔离测试通过两个独立 Viewer 的 API 响应和固定测试状态验证。界面需明确标记“开发实验台，不提供真实账户隔离”。

### 11.3 最小内存 runner

实现创建、读取指定测试座位视图、提交动作和释放对局。成功动作 revision 加 1；收到旧 expectedRevision 返回 STATE_CONFLICT，不更新状态。非法动作不修改 State/RNG/revision。

本阶段内存状态在重启后丢失，必须在界面和 README 明示。去重持久化、自动重发、事务恢复在阶段 4 完整实现，本阶段不要自动重试有副作用的请求，也不宣称恢复保障已完成。

默认最多 20 个测试对局，空闲 30 分钟回收，删除/到期后返回 MATCH_NOT_FOUND，关闭服务释放内存。测试可注入时钟验证回收，不能在规则代码调用时钟。

## 12. HTTP 接口

默认统一前缀 /api/v1，公开健康检查可放 /health。下列开发接口只在双重开发开关下注册。

| 方法与路径 | 用途 | 阶段 1 行为 |
| --- | --- | --- |
| GET /health/live | 进程存活 | 200，不依赖数据库 |
| GET /health/ready | 数据库、迁移和注册表就绪 | 就绪 200，否则 503；不泄露连接串 |
| GET /api/v1/games | 已启用扩展公开目录 | 返回真实注册元信息，未知内部字段不透传 |
| GET /api/v1/games/:id/versions/:version | 扩展详情 | 公共 manifest，无源码或私密实现 |
| POST /api/v1/dev/lab/matches | 创建测试对局 | 输入 gameId、version、options；座位由服务端固定生成 |
| GET /api/v1/dev/lab/matches/:id/view?seat=... | 测试身份视图 | 只返回该座位投影 |
| POST /api/v1/dev/lab/matches/:id/actions | 提交测试动作 | 校验 testSeatId、requestId、expectedRevision、action |
| DELETE /api/v1/dev/lab/matches/:id | 释放实验台对局 | 成功返回 204，重复删除亦可 204 |

所有开发查询只操作实验台内存空间，不能传入真实 roomId 或访问正式业务表。开发创建默认返回第一个座位的视图及测试座位列表，不返回 State。

### 12.1 响应约定

成功 envelope：ok=true、data、traceId。错误：ok=false、error={code,message,retryable}、traceId。204 无 body。traceId 是追踪请求的 ID，与动作去重 requestId 区分。

动作成功返回 revision、view、可见 events、delivery="live"。读取和创建快照返回 delivery="snapshot"，不触发瞬时音效。catch-up 预留给恢复阶段。

错误码至少覆盖 VALIDATION_ERROR（400）、GAME_NOT_FOUND（404）、MATCH_NOT_FOUND（404）、STATE_CONFLICT（409）、ACTION_NOT_ALLOWED（422）、RATE_LIMITED（429）、SERVICE_UNAVAILABLE（503）、INTERNAL_ERROR（500）。认证阶段再接入 UNAUTHENTICATED/FORBIDDEN。注册表版本不兼容在启动时失败，不隐藏成普通 404。

未知字段严格拒绝，字符串长度与数组长度有边界；开发动作请求默认上限 64 KiB。5xx 对外仅提供安全消息与 traceId，完整异常只进入脱敏服务端日志。

## 13. WebSocket 协议

阶段 1 只实现 /api/v1/ws 的无业务数据 ping/pong，用于检验真实连接、解析和清理。不是正式对局订阅。

客户端消息：protocolVersion=1、type="ping"、requestId。服务端返回相同 requestId、type="pong"、protocolVersion=1。连接建立可发送 type="hello"，包含协议版本，不包含服务器秘密或数据库信息。

无效 JSON、未知类型、错误版本返回协议错误；超限消息关闭连接；限制频率并测试。默认消息体最大 8 KiB，默认每连接每秒 5 条，空闲 60 秒关闭。清理定时器，不做无限重连循环。客户端重连使用有上限退避，只用于状态诊断，卸载页面停止。

开发和生产均校验允许的 Origin；生产默认同源。无 Origin 的非浏览器客户端规则显式配置，本阶段默认拒绝。不要把公开 ping/pong 端点视为认证完成；未来房间消息必须另做身份验证与订阅授权。

在 protocol 中定义未来 GameCommand 与 PlayerSnapshot 的 schema，但不注册正式动作路由。snapshot 只容纳玩家 View，禁止 field 名为 fullState 的通用后门。

## 14. 数据库基础

本阶段实际建立：

| 表 | 字段 | 约束 |
| --- | --- | --- |
| schema_migrations | version、checksum、applied_at | version 唯一，已应用迁移不可静默改写 |
| game_installations | game_id、game_version、content_version、sdk_range、manifest JSONB、enabled、installed_at | (game_id, game_version) 复合主键 |

数据库使用参数化查询，迁移在显式命令中执行，不在每次 HTTP 请求执行。提供扩展同步命令幂等写入开发扩展；同一版本已有不同 manifest 时失败并要求升级版本，不覆盖旧含义。数据库记录不保存可执行源代码。

启动失败与就绪失败行为：环境错误直接退出；数据库暂不可用可启动 live，但 ready 为 503，依赖数据库的目录接口返回 SERVICE_UNAVAILABLE，不伪造为空列表。迁移缺失时给出执行命令；恢复连接后 ready 能恢复。

生产就绪忽略 developmentOnly 扩展，即使开发数据库残留其安装记录，也不加载它。

## 15. 图片与音效契约

本阶段实际实现资源 manifest schema、静态示例和资源 ID 查找；不实现上传管理。

资源条目区分 image 与 sound，字段包含 id、相对 file、mediaType、可选来源/许可。image 包含 width/height；sound 包含 durationMs。先只接受 PNG/JPEG/WebP、MP3/WAV，路径禁止绝对路径和 ..；URL 通过可信资源解析器生成，客户端不能凭路径访问任意服务器文件。

未来上传限制沿用任务书：单文件默认 10 MiB、单包 100 MiB、短音效最长 15 秒，可配置；本阶段 schema 校验声明，真实字节/时长验证在上传阶段完成，不混淆两者。

声音映射单独保存：eventType → soundId、channel（game/ui）、gain（0–1）、cooldownMs、priority、maxConcurrent。所有字段有有界 schema；soundId 引用不存在时报告明确错误。采用自制短 WAV 或小型 fixture 验证映射，无需在网页播放。

AudioPort 只定义 unlock、play、setPreferences、stopAll、dispose 等类型，不创建返回成功的假实现。声音只能来源于可见事件，snapshot/catch-up 不触发瞬时声音。未来后台抑制、多标签页主控、音量、去重和加载失败降级均由平台 AudioManager 完成。

StorageAdapter 定义 put/get/delete 和对象元信息职责，但本阶段静态资源走应用静态目录，无需假装对象存储已实现。规则只引用逻辑 ID，不写绝对图片 URL、音频路径或存储凭据。

## 16. AI 与控制器预留

只定义类型和设计说明，不创建空轮询 worker：

- Controller：human、script、model；附 controllerEpoch。
- DecisionInput：matchId、seatId、revision、decisionId、controllerEpoch、View、ActionSpec、公开规则摘要。
- DecisionResult：action、可选简短公开说明、可选用量信息。
- DecisionProvider：decide(input, abortSignal) 返回结构化结果。

类型不能把 State 或数据库连接传入 provider。getFallbackAction 为测试扩展提供最简单实现：轮到自己则 add 1，否则 null；这只是接口示例，不代表 AI 对局完成。

后续任务绑定 revision/decisionId/controllerEpoch，收回控制使旧结果失效。模型调用失败有限重试后合法兜底，没有合法动作则等待。未来模型密钥只在服务端，阶段 1 启动不要求任何 AI 密钥。

顶部是“桌游平台”和简单导航，主体为已注册游戏卡片。每卡显示名称、描述、人数、版本；开发扩展标记“测试”。加载、空列表和网络错误分别呈现，错误提供重试按钮。生产版本无游戏时显示“尚未安装游戏”，不是安装成功提示。

分开展示 API、数据库就绪和实时连接状态，不能合并成一个永远绿色的“在线”。显示最近检查时间与可选往返耗时；不展示环境变量、主机凭据和原始堆栈。提供主动重新检查，不进行高频无休止轮询。

### 17.4 开发实验台

显示显眼的开发用途提示、游戏选择、目标分数输入、创建按钮。创建后展示两个座位的公开分数、当前行动方、本人私密提示、revision 和经过过滤的事件。动作按钮为“加 1”“加 2”；不是自己行动、已结束或正在提交时禁用。

切换测试座位后重新请求视图，不从缓存完整状态生成。拒绝显示安全原因；状态冲突重新获取视图，要求用户再次确认动作，不自动重放。重开释放旧实验台对局并创建新 ID。服务重启后找不到对局时提示重新创建，不假装恢复成功。

UI 只使用 view 和 sendAction，由注入的 client adapter 通信，不导入规则实现。实验台可以有用于验证的技术字段，普通首页不展示这些字段。

### 17.5 视觉默认值

采用浅色、中性色桌面风格：背景 #F5F3EE、面板 #FFFFFF、正文 #202522、强调色 #315C4B。颜色以 CSS 变量存储，不在组件散落硬编码。字体使用系统中文字体栈，不依赖外部字体 CDN。

基础间距 4/8/12/16/24/32px；圆角 8/12px；正文约 16px。按钮点击区域默认至少 44px 高；保留键盘焦点，状态同时使用文字，不能仅靠颜色。390px 宽度下无整页意外横向滚动，1440px 下内容居中且不过度留白。

此阶段不做品牌插画、复杂动效或完整卡牌设计。尊重减少动画偏好，加载状态和错误状态必须真实可见。
