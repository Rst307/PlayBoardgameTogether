# 璀璨宝石

games/splendor 提供 splendor.base@1.0.0，在大厅创建房间时选择「璀璨宝石」。支持 2–4 个真人／专用脚本 AI 座位，沿用登录、准备、开局、正式动作、模型候选、持久化恢复与结算后房间复位。

## 规则与操作

- 90 张发展卡按等级分为 40/30/20 张；每级公开四张。2/3/4 人每种宝石分别 4/5/7 枚，黄金五枚，公开人数加一位贵族。座位 1 为起始玩家。
- 直接点击库存选择宝石，不再切换拿取方式：点击三种不同颜色，或连续点击同色两次，再「确认拿取」。同色双拿要求库存至少四枚；不足三种颜色时必须拿全部可用颜色。非法混拿、第四种颜色、空库存和直接拿黄金会在库存旁说明原因，并保留原选择。已选筹码可逐枚取消，也可清空；再次点击已选的混色筹码会取消该色，第三次点击同色双拿会清空。
- 点击发展卡放大查看费用，再在屏幕内的确认面板「确认购买」或「确认预留」。等待对手时也可查看卡牌；购买／预留仅在本人可行动时启用。Esc 或「取消选择」关闭草稿。预留最多三张，拿一枚黄金；黄金用完也能预留。点击等级牌背，再「确认盲抽预留」可以预留牌堆顶牌。
- 购买可用永久同色折扣抵扣费用，剩余用代币支付。默认优先普通宝石，可展开「调整黄金替代」主动保留普通宝石；费用不足或黄金超支不能确认。
- 拿取／预留导致代币超过十枚时，逐枚选择退回，包括黄金或本回合刚拿的宝石；回合和退币阶段均保存在服务端。
- 达到贵族的永久折扣要求则获得三声望，多个满足时自行选择一位，每回合最多一位，随后结束回合。
- 回合结束有人达到十五声望时，继续到最后一个座位，保证每人回合数相同。最高声望胜，同分时购买发展卡更少者胜，仍相同共享胜利。
- 全员完全无可用主行动的极端僵局，平台允许被迫跳过，并在全部连续跳过后按正常排名结束；此为明确的数字版恢复规则。

对手只见预留数量，不见预留卡身份或牌堆顺序；自己预留的卡刷新后保留。动作请求复用平台身份、revision、receipt 和事务，游戏不接受账户或座位授权字段。公开事件不携带盲抽／预留卡身份。AI 只用本人 View 和合法候选；黄金支付候选枚举所有有效组合。脚本策略优先购买高分卡和积攒接近目标卡的宝石，退币和贵族选择仍走同一校验。

## 桌面与行动反馈（2026-10-02）

深绿桌面与金色当前回合标识，库存和贵族在桌面上方并排，三层市场保持四列；卡面高度按视口约束，预留卡、本人和对手商会放在侧栏。小尺寸桌面可同时看到完整市场；较多玩家／已购卡／记录在侧栏内滚动，规则、声音与托管工具位于棋盘之后。手机自然纵向滚动，避免卡牌撑出横向宽度。

公开行动记录展示拿取、购买、公开／盲抽预留、退币和贵族到访。最近行动在视口内停留五秒；购买展示公开卡面、声望和新增折扣，并播放短进入动画。记录保留最近六条；刷新／恢复不补播历史，重复 eventId 不重复展示，减少动态效果偏好停用动画。对手预留卡身份仍不展示。既有公开拿取／退币事件不含具体颜色，记录按真实事件显示行动类型，不猜测明细。

## 图形与来源

2026-10-02 支持两套图包：默认「原创几何 SVG」splendor.original@1.0.0，以及「TTS 经典卡面」splendor.tts-classic@1.0.0。房主在等待房间的「资源包」中选择，更换取消真人准备，开局同事务锁定精确清单。旧局空绑定继续使用原创 SVG，不改写旧规则/资源摘要。贵族中文名称仍为原有功能别名。

独立 ./assets 入口声明 109 个可选图片槽位：90 张发展卡、10 位贵族、3 级牌背和 6 种筹码。原创版本为空图片映射，由客户端 SVG 提供；TTS 版本完整映射，图片通过已鉴权平台资源接口读取，不使用运行时外链。经典卡面在桌面使用完整缩略图并单独显示清晰的声望、永久折扣和费用；手机保留紧凑四列卡面，点击可查看大图及语义费用。规则数值和操作提示仍来自 View。加载失败恢复对应原创图形和合法按钮，管理页可固定预览全部槽位。没有新增音效。

TTS 图片来自用户提供的 Workshop 2023213924 本地缓存，按牌面颜色/声望/费用逐项映射；筹码将原 UV 首个椭圆面校正为透明圆形。素材未附开放许可，不作为官方授权或 CC0 素材提交 GitHub。提取与准备文件保存在本地 .data；发行商插画版权与原创 SVG 分开记录。

本机已提取图包的安装步骤：

```powershell
python scripts/prepare-splendor-tts.py '.data/extracted-assets/splendor-tts-2023213924' '.data/extracted-assets/splendor-tts-platform'
pnpm assets:seed
```

准备脚本拒绝覆盖已有目录。已准备无需重复生成，种子可重复执行，精确已发布版本不覆盖；中断时复用相同原文件哈希的已校验文件，失败媒体用新回执最多重试三次。也可设置 SPLENDOR_TTS_ASSET_DIR 为包含 files.json 的准备目录。没有本地素材的新环境只安装原创版本，完整恢复须备份数据库和 .data/assets；不在新环境猜测或自动下载素材。详见 [TTS 提取说明](splendor-tts-extraction.md)。

规则核对：[Space Cowboys / Asmodee 官方规则书](https://cdn.svc.asmodee.net/production-asmodeeca/uploads/2022/01/SCSPL01EN_SPLENDOR_RULES_LIGHT.pdf)。基础牌数值参考 [牌表一](https://github.com/bouk/splendimax/blob/master/Splendor%20Cards.csv) 和 [牌表二](https://github.com/seal256/splendor/blob/master/assets/cards.csv)（90 张逐项一致，固定 SHA-256 黄金回归），仅转录功能数值，未复制引擎或插画。牌表保存在 src/shared/catalog.ts，规则摘要覆盖牌表、shared/server 源码和 SDK，不改写旧游戏版本。

## 维护

- 游戏服务端仅在 API registry 装配，浏览器入口仅在 Web game-registry 装配。
- AI worker 只新增可信策略装配项；房间／正式动作／实时通信／认证模块无需游戏分支。
- pnpm games:sync 安装精确 manifest，新增包不需要数据库迁移。
- 存档检查卡牌／贵族唯一性与守恒、代币守恒、等级、补牌、退币阶段和最终排名；最终分数比较不依赖 PostgreSQL JSONB 对象键顺序。
- 首版浏览器验收截图保存在 docs/screenshots/splendor/；本轮界面截图保存在本地 .data/e2e-splendor-ui/，含用户 TTS 图片的截图不提交仓库。
十位贵族功能要求另核对 [完整贵族表](https://github.com/seal256/splendor/blob/master/src/splendor.cpp)：五个相邻双色四折扣和五个相邻三色三折扣，采用独立黄金回归验证。

## 交互上手教程（2026-10-03）

游戏详情点击「进入教程」，或打开 `/games/splendor.base/1.0.0/tutorial`。无需登录，复用真实璀璨宝石桌面，依次练习三色拿取、同色双拿、购买、永久折扣、公开预留、盲抽预留、黄金购买预留卡、超过十枚退币、多个贵族选择、触发最终轮及最后座位结算。每课使用独立固定场景，完成后点击下一步；支持重试、上一步、重新开始，刷新回到第一课。不创建房间、不发送正式动作、不保存成绩。

教程通过独立 `@boardgame/splendor/tutorial` 客户端导出按精确版本延迟加载，普通正式对局不加载练习数据。固定场景只保存合成公开 View 和投影事件，没有完整 State、牌堆顺序或他人预留身份。`tests/unit/splendor-tutorial-reference.ts` 的合成参考状态仅供开发/测试，用真实 server 校验所有动作和完整结果；修改练习场景后执行 `pnpm exec tsx scripts/generate-splendor-tutorial.ts` 更新客户端公开投影源文件，再运行相关单元/E2E 验证。该命令不读取数据库、不访问外部服务、不重写规则源文件。
