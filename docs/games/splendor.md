# 璀璨宝石

games/splendor 提供 splendor.base@1.0.0，在大厅创建房间时选择「璀璨宝石」。支持 2–4 个真人／专用脚本 AI 座位，沿用登录、准备、开局、正式动作、模型候选、持久化恢复与结算后房间复位。

## 规则与操作

- 90 张发展卡按等级分为 40/30/20 张；每级公开四张。2/3/4 人每种宝石分别 4/5/7 枚，黄金五枚，公开人数加一位贵族。座位 1 为起始玩家。
- 点击库存选择三种不同颜色，再「确认拿取」。不足三种时必须拿全部可用颜色。选择「两枚同色」时，该颜色库存须至少四枚。黄金不能直接拿取。
- 点击发展卡，再在固定于屏幕底部的确认面板「确认购买」或「确认预留」。预留最多三张，拿一枚黄金；黄金用完也能预留。点击等级牌背，再「确认盲抽预留」可以预留牌堆顶牌。
- 购买可用永久同色折扣抵扣费用，剩余用代币支付。默认优先普通宝石，可展开「调整黄金替代」主动保留普通宝石；费用不足或黄金超支不能确认。
- 拿取／预留导致代币超过十枚时，逐枚选择退回，包括黄金或本回合刚拿的宝石；回合和退币阶段均保存在服务端。
- 达到贵族的永久折扣要求则获得三声望，多个满足时自行选择一位，每回合最多一位，随后结束回合。
- 回合结束有人达到十五声望时，继续到最后一个座位，保证每人回合数相同。最高声望胜，同分时购买发展卡更少者胜，仍相同共享胜利。
- 全员完全无可用主行动的极端僵局，平台允许被迫跳过，并在全部连续跳过后按正常排名结束；此为明确的数字版恢复规则。

对手只见预留数量，不见预留卡身份或牌堆顺序；自己预留的卡刷新后保留。动作请求复用平台身份、revision、receipt 和事务，游戏不接受账户或座位授权字段。公开事件不携带盲抽／预留卡身份。AI 只用本人 View 和合法候选；黄金支付候选枚举所有有效组合。脚本策略优先购买高分卡和积攒接近目标卡的宝石，退币和贵族选择仍走同一校验。

## 图形与来源

原创 SVG 切面宝石、矿场／商会／宫殿线描与贵族纹章直接随客户端编译；没有外链图片、商业原版插画、字体下载或运行时绘图服务。贵族中文名称是原创。默认资源清单 splendor.original@1.0.0 为空，矢量图由客户端语义组件提供；本轮不提供管理员替换图包或新增事件音效。

规则核对：[Space Cowboys / Asmodee 官方规则书](https://cdn.svc.asmodee.net/production-asmodeeca/uploads/2022/01/SCSPL01EN_SPLENDOR_RULES_LIGHT.pdf)。基础牌数值参考 [牌表一](https://github.com/bouk/splendimax/blob/master/Splendor%20Cards.csv) 和 [牌表二](https://github.com/seal256/splendor/blob/master/assets/cards.csv)（90 张逐项一致，固定 SHA-256 黄金回归），仅转录功能数值，未复制引擎或插画。牌表保存在 src/shared/catalog.ts，规则摘要覆盖牌表、shared/server 源码和 SDK，不改写旧游戏版本。

## 维护

- 游戏服务端仅在 API registry 装配，浏览器入口仅在 Web game-registry 装配。
- AI worker 只新增可信策略装配项；房间／正式动作／实时通信／认证模块无需游戏分支。
- pnpm games:sync 安装精确 manifest，新增包不需要数据库迁移。
- 存档检查卡牌／贵族唯一性与守恒、代币守恒、等级、补牌、退币阶段和最终排名；最终分数比较不依赖 PostgreSQL JSONB 对象键顺序。
- 浏览器验收截图保存在 docs/screenshots/splendor/。
十位贵族功能要求另核对 [完整贵族表](https://github.com/seal256/splendor/blob/master/src/splendor.cpp)：五个相邻双色四折扣和五个相邻三色三折扣，采用独立黄金回归验证。
